# repocast

**Generate a narrated walkthrough video of any code project — no screen recording.**

Point `repocast` at a repo with a `walkthrough.yaml` and it produces a 1080p MP4 that
walks your **design doc**, runs your **real tests/demo** in a terminal, and drives your
**live app** in a browser — with an **AI voice-over** paced to the narration. Upload the
result to YouTube/Loom/Jam. It also emits a timestamped `NARRATION.md` if you'd rather
record in your own voice.

Great for take-home submissions, README demos, onboarding, release notes, and OSS intros.

> Unlike browser-only demo tools, repocast narrates the **whole project** — docs + terminal
> + app — and needs **no terminal emulator** (it renders captured stdout itself), so it
> runs on headless servers and Wayland boxes.

## Install

**As a CLI:**
```bash
uv tool install git+https://github.com/jd316/repocast   # or: pipx install …
playwright install chrome                                # one-time browser
```

**As a Claude Code skill** (so it triggers on "make a walkthrough video"):
```
/plugin marketplace add jd316/repocast
/plugin install repocast@repocast
```
The skill drives the CLI, so install both. (Or clone this repo and copy
`skills/repocast/` into `~/.claude/skills/`.)

## Quick start

```bash
repocast init walkthrough.yaml     # scaffold, then edit it
export GEMINI_API_KEY=...           # https://aistudio.google.com/apikey
repocast voices                     # (optional) pick a voice
repocast render walkthrough.yaml    # -> walkthrough.mp4 + NARRATION.md
```

Prefer your own voice? `render --no-voice` (or `tts: {provider: none}`) makes a silent
video; read the generated `NARRATION.md` over it.

No install? Run from a source checkout with
`uv run --with pyyaml --with playwright --with markdown python3 -m repocast <cmd>`.

## Requirements
- Python 3.10+, `ffmpeg` + `ffprobe`, and Chrome/Chromium (Playwright uses the system Chrome).
- A [Gemini API key](https://aistudio.google.com/apikey) for narration (or use `--no-voice`).
- Your project must be runnable (its tests/demo commands and, for the app segment, its start command).

## The config

Three optional segment types. Full schema in [`examples/walkthrough.yaml`](examples/walkthrough.yaml);
a complete real example in [`examples/terrabase.yaml`](examples/terrabase.yaml).

```yaml
output: walkthrough.mp4
size: [1920, 1080]
tts: { provider: gemini, voice: Charon, model: gemini-3.1-flash-tts-preview }
segments:
  - doc:                                  # scroll a rendered markdown doc, section by section
      file: DESIGN.md
      steps:
        - { anchor: architecture, say: "The system is layered…" }
  - terminal:                             # run real commands, film their real output
      cwd: .
      steps:
        - { run: ["make", "test"], say: "The test suite — green." }
  - app:                                  # drive the live app in a browser
      cwd: .
      start: ["make", "run"]
      url: "http://127.0.0.1:8000"
      ready_path: /health
      zoom: 1.4
      actions:
        - { say: "Here it is running for real." }
        - { click: "#submit" }
        - { wait_for: ".result", timeout: 60000 }
        - { say: "…and the result comes back." }
```

App action verbs: `say`, `click`, `fill` (+`value`), `wait_for` (+`timeout`), `press`,
`goto`, `eval`, `sleep`. Doc `anchor`s are the rendered heading IDs (lowercase,
spaces→hyphens); a wrong anchor is a **loud error**, never a silently dropped section.

## CLI

| Command | What |
|---|---|
| `repocast init [path]` | scaffold a `walkthrough.yaml` template |
| `repocast render <config>` | build the narrated MP4 + `NARRATION.md` |
| `repocast validate <config>` | check a config without rendering |
| `repocast voices` | synthesise sample clips to choose a voice |
| `repocast verify <video>` | check a rendered video (audio present + is speech, cue alignment) |

## How it stays in sync (the design choice that matters)

**Audio-first.** Narration is synthesised and its real duration **measured** *before*
recording; every on-screen hold is at least as long as the line spoken over it, and each
clip is muxed at its exact cue offset. The video is paced to the speech — never the other
way round (which drifts). `render` regenerates the video and `NARRATION.md` together, so
they can't fall out of step.

## Notes learned the hard way
- Uses `gemini-3.1-flash-tts-preview` — the 2.5 TTS models silently refuse some lines under
  a style prompt. All lines are pre-flighted (fail fast) with a bare-text fallback.
- Verify by **looking at a frame**, not md5/`freezedetect` — h264 quantization noise makes
  visually-static frames differ bit-for-bit, so those tools misreport holds. `repocast verify`
  checks audio + alignment and tells you to eyeball a frame.
- Don't hardcode narration numbers that differ per backend (mock vs real model); describe the
  behavior or read it from the live response.

## For take-home / interview submissions
The "explain your tradeoffs" step is meant to show *your* communication. Consider rendering
`--no-voice` and recording `NARRATION.md` in your own voice — repocast then just handles the
tedious, repeatable capture and timing.
